3.1 Complete Data Dictionary (តារាងទិន្នន័យទាំង ៨ លម្អិត)

មូលដ្ឋានទិន្នន័យរបស់ប្រព័ន្ធ TechTonic Store ត្រូវបានរៀបចំឡើងយ៉ាងត្រឹមត្រូវតាមស្ដង់ដារ Third Normal Form (3NF) ដោយបែងចែកជា ៨ តារាង គ្មានទិន្នន័យស្ទួន និងមាន Referential Integrity ពេញលេញ៖

Table Name Primary Key Foreign Key (FK) Reference Data Types Used តួនាទី & ការពិពណ៌នា (Purpose)
users id None (Root Entity) UUID, VARCHAR ផ្ទុកព័ត៌មានគណនីអតិថិជន និង Admin (`customer`, `admin`)

3.2 Comprehensive Cardinality & Relationships Matrix

ទំនាក់ទំនង (Relationship) Cardinality Foreign Key Binding ការពន្យល់បច្ចេកទេស (Technical Explanation)
users → user_addresses 🌿 1 : N user_addresses.user_id អតិថិជនម្នាក់ (1 User) អាចកត់ត្រាអាសយដ្ឋានដឹកជញ្ជូនបានច្រើន (Many Addresses)។
categories → products 🌿 1 : N products.category_id ប្រភេទទំនិញមួយ (1 Category) ផ្ទុកទំនិញជាច្រើនមុខ (Many Products)។
users → orders 🌿 1 : N orders.user_id អតិថិជនម្នាក់ (1 User) អាចបញ្ជាទិញទំនិញបានច្រើនដង (Many Orders) តាមពេលវេលាផ្សេងគ្នា។
orders ↔ products 🔮 N : N via order_items ការកុម្ម៉ង់ម្តងមានទំនិញច្រើនមុខ ហើយទំនិញមួយមុខអាចមានក្នុង Order ច្រើនដង (បំបែកតាម Junction Table)។
products → product_reviews 🌿 1 : N product_reviews.product_id ទំនិញមួយមុខ (1 Product) អាចទទួលបាន Review និងផ្កាយពីអតិថិជនជាច្រើន។
users → product_reviews 🌿 1 : N product_reviews.user_id អតិថិជនម្នាក់ (1 User) អាចសរសេរ Review លើទំនិញផ្សេងៗបានច្រើនដង។

3.3 Entity Relationship Diagram (ERD) — Visual Schema

ខាងក្រោមនេះជាប្លង់ Entity Relationship Diagram (ERD) ពេញលេញដែលបង្ហាញពីតារាងទាំង ៨, Primary Keys, Foreign Keys និងខ្សែភ្ជាប់ទំនាក់ទំនង Cardinality ត្រឹមត្រូវ 100%៖

PK: Primary Key
FK: Foreign Key
1 : N: One-to-Many
N : N: Many-to-Many (via order_items)
